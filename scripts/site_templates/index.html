The product

Then one line: how many of its wrappers have a CMC-tracked market, and whose. The answer below is a committed run; type any ticker to ask live.

The API

{{api_count}} endpoints. Two of them are the whole join.

The wrapper roster with its null-price rows exists in one place: tokens[] on /v5/real-world-assets/quotes/latest. The listing state that explains the nulls exists in one place: status on /v1/cryptocurrency/map. Delete CoinMarketCap and both ledgers vanish — no single endpoint says a wrapper has no market; only the join does.

The map's symbol= filter rejects symbols CoinMarketCap itself assigns — NVDA.D, AI.FRx — with HTTP 400 for the whole call, and the map has no id= filter to fall back to. Those rows take their live state from /v2/cryptocurrency/info?id=, whose vocabulary is coarser; each row names both sources.

Questions a judge will ask

Honest limits.

Is this page live?

The census and the {{hero_symbol}} answer are committed runs — {{generated_short}} UTC and {{hero_asked}} UTC — and say so on every number. The ticker box is live through two proxy functions: the roster leg keyed on the site's key (or the committed snapshot, labelled), the state leg keyless. The proxy shares one IP against a per-IP anonymous limit, so a 429 is shown as a 429 with the command to run instead; the CLI is the primary live path, and every reader has their own quota there.

What does "untracked" mean?

It is CoinMarketCap's listing state, quoted from its map documentation: "{{definition}}". On this page it reads listed, no CMC-tracked market. It does not mean never traded: Dinari dShares trade on Dinari's own venue, and some wrappers may sit in pools CMC does not index. The number is about CoinMarketCap's coverage of what CoinMarketCap calls tokenised — which is why it can be re-derived. The spike that settled the wording: spike.json↗ (opens in a new tab).

Why {{hero_symbol}}?

A rule, not a pick: {{hero_rule}} — {{hero_symbol}}, rank {{hero_rank}}, the only all-shelf underlying inside CMC's top 50. Next in line: {{runners_up}}. If tomorrow's census promotes its wrapper to active, the rule moves on and the delta panel shows the flip — a shelf wrapper coming alive is the strongest proof the census is live.

Which rows are not counted?

{{unresolved}} wrapper ids resolve on no public CMC surface ({{unresolved_list}}); they are shown in their own bucket and excluded from every count. {{dotted}} wrappers carry a dotted symbol the map filter rejects; their live state comes from /v2/cryptocurrency/info and the map's finer word from the committed snapshot, and each row says which. num_tokens on the issuer registry is undocumented, so it is shown as "declared" and never substituted for attached (Backed declares {{backed_declared}}, {{backed_attached}} are attached).

How old is the series?

A daily series, not a history: {{snapshots_list}}. Untracked map rows carry no dates of their own, so the only time axis is the snapshot series this repository records; date_added from the info endpoint is a listing day, not a market day. The roster leg needs a key (the RWA family answers keyless calls with 403 error 1005); without one it is a dated snapshot, labelled on the row, and the state leg is live regardless.

What is not built?

No price charts, no wrapper-versus-underlying spread, no portfolio, no alerts, no watchlists, no model, no chain, no wallet, no LLM. The product counts the shelf and answers a ticker beside its raw rows; that verb is the whole scope, and the rule that produces the number is printed, never widened.
